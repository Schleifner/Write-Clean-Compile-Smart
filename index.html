Some developer may bench the performance by following code 
int main(){
    int startTime1 = getTime();
    for(int i = 0; i<10000000;i++){

    }
    int endTime1 = getTime();
    int timeCost1 = endTime1-startTime1;
    print(timeCost1);
    int startTime2 = getTime();
    for(int i = 0; i<10000000;++i){
    
    }
    int endTime2 = getTime();
    int timeCost2 = endTime2-startTime2;
    print(timeCost2);
}
Question: Which one is correct
A: I did similar bench in the past  |  B: No, I didn't
Answer:
compiler can optimize out empty blocks including empty if/for/while etc. So the code become: 
int main(){
    int startTime1 = getTime();
    int endTime1 = getTime();
    int timeCost1 = endTime1-startTime1;
    print(timeCost1);
    int startTime2 = getTime();
    int endTime2 = getTime();
    int timeCost2 = endTime2-startTime2;
    print(timeCost2);
}
So the final timeCost1 and timeCost2 are very small numbers. And the actual value depends on the OS interference factors, such as scheduling and timer interrupt.

Question: Which way should we use to swap two variables? Is avoiding temp faster?
Answer:
On modern processors, a normal variable swap can be handled efficiently with registers and register renaming. XOR swapping occupies the ALU with several dependent instructions, so instruction-level parallelism is poor.

how to iterate over an array
05 / 14 
for(int i = 0;i<array.size();i++){

}
int size = array.size();
for(int i = 0;i<size;i++){
    
}
Question: which one is faster? why?
Answer:
Compiler has loop invariant code motion. The array.size() function will be called multi times during the loop when the array size is unchanged in the loop. Moreover, compiler also inline small function calls, so the .size() function call will not exist. Instead, it will be optimized to array._size attribute read.
int size = array.size(); is also not a performance problem, because compiler has variable liveness analysis. The storage allocated for int size can be reused by other variables after the for loop.

named constants vs magic number
06 / 14 
int hoursInDay = 24;
int minutesInHour = 60;
int secondsInMinute = 60;

int secondsInDay = hoursInDay * minutesInHour * secondsInMinute;
int secondsInDay = 86400;
Question: Which version is easier to understand? Does the first version do more work at runtime?
Answer:
The named constants make the units and intent clear. The compiler has const propagation to calculate the product ahead of time, so the first version does not need to perform those multiplications at runtime.
Prefer the readable version over the magic number. One more note, some programming language can declare variable as const, but compiler const propagation doesn't rely on the const qualifier.

wrong data structure selection

array<int> container;
void producer(int value){
    container.push(value);
}

void consumer(){
    for(value of container){
        //some code
    }
}
set<int> container;
void producer(int value){
    container.push(value);
}

void consumer(){
    for(value of container){
        //some code
    }
}
list<int> container;
void producer(int value){
    container.push(value);
}

void consumer(){
    for(value of container){
        //some code
    }
}
Question: Which has better performance? Why?
Answer:
The data is only pushed and iterated in a linear way and array push is O(1) and array is in a contiguous memory which is more cache friendly. set is usually implemented by hash map or RB-Tree. Hash map has hash value overhead and RB-Tree is O(logn). Moreover, hash map, RB-Tree and linked list are not memory contiguous as array.
And most compilers doesn't have modeling and analysis of data structures. So if the data structures are chosen wrong, the code remains slow.
